
# GBitcoin Security Policy

## 1. Security Commitment

Security is a fundamental consideration in the development, operation, and long-term sustainability of GBitcoin (GBTC).

The GBitcoin project recognizes the importance of protecting users, maintaining the integrity of project infrastructure, and ensuring the reliability of its official resources.

This security policy establishes the principles, procedures, and responsible disclosure practices for identifying, reporting, assessing, and addressing potential security vulnerabilities.

## 2. Scope of Security

This policy applies to security issues affecting officially maintained GBitcoin resources, including:

- Official project repositories and source code.
- Official website and web infrastructure.
- Project-maintained software and technical components.
- Official project documentation and associated services.
- Security-sensitive configurations and integrations maintained by the project.

Issues involving third-party platforms, external services, or independently operated infrastructure may fall outside the direct control of the GBitcoin project.

## 3. Responsible Vulnerability Disclosure

GBitcoin encourages responsible security research and appreciates individuals who help identify potential vulnerabilities.

Security researchers are requested to report discovered vulnerabilities privately and provide sufficient technical information to support investigation and verification.

Reports should include:

- A clear description of the identified vulnerability.
- The affected component or resource.
- Reproduction steps, where applicable.
- Potential security impact.
- Supporting technical evidence or proof of concept.
- Any suggested remediation, if available.

Please avoid including private keys, seed phrases, passwords, or other sensitive user information in vulnerability reports.

## 4. Vulnerability Reporting

Potential security vulnerabilities should be reported through an appropriate private communication channel.

Where GitHub Private Vulnerability Reporting is enabled for the relevant repository, researchers may use that mechanism to submit confidential reports.

Public disclosure of unpatched vulnerabilities is strongly discouraged.

Security reports should not be submitted through public issues or public discussions.

## 5. Security Assessment and Response

Reported vulnerabilities may be evaluated according to several factors, including:

- Severity and potential impact.
- Exploitability and attack complexity.
- Scope of affected components.
- Potential risks to users and project infrastructure.
- Availability and feasibility of remediation.

Depending on the findings, appropriate actions may include investigation, corrective changes, security updates, configuration improvements, or additional technical review.

The handling and resolution time of each report may vary depending on its complexity and severity.

## 6. Responsible Research Principles

Security researchers are expected to:

- Act in good faith and avoid unauthorized access.
- Avoid disrupting services or degrading system availability.
- Never access, modify, or disclose other users' private information.
- Avoid actions that could result in financial loss or asset exposure.
- Refrain from exploiting vulnerabilities beyond what is necessary to demonstrate their existence.
- Allow reasonable time for investigation and remediation before public disclosure.

## 7. Security Updates and Transparency

Security-related improvements and relevant updates may be communicated through official GBitcoin project channels when appropriate.

The project aims to maintain clear documentation and provide accurate information regarding security-related changes.

No security system or software infrastructure can be guaranteed to be completely free of vulnerabilities.

## 8. Third-Party Dependencies

External libraries, development tools, hosting providers, blockchain infrastructure, and third-party services may introduce risks outside the direct control of the project.

Such dependencies should be evaluated according to their relevance, availability, and potential security impact.

## 9. Security Limitations

This policy does not constitute a guarantee of security, a formal security certification, or evidence of an independent security audit.

It establishes the project's approach to responsible vulnerability reporting, security assessment, and ongoing improvements.

No bug bounty program or financial reward is implied by this policy unless separately announced through an official GBitcoin communication channel.
